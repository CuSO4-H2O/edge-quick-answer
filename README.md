# 划词答题助手（Edge 扩展）

edge搜索“划词答题助手”应该能找到（前提是插件过审了，提交申请时间为10.13）
在网页上**选中文字**或按快捷键，侧边栏立即用 DeepSeek 流式给出答案与理由。面向"网页上快速做题"的场景，同时保留完整的多轮追问能力。

## 一、装上试一下（约 1 分钟）

1. 构建：
   ```powershell
   pnpm install
   pnpm build
   ```
2. 打开 Edge，地址栏输入 `edge://extensions/`
3. 打开左下角 **开发人员模式**
4. 点 **加载解压缩的扩展**，选择本项目的 **`dist` 目录**（不是项目根目录）
5. 点扩展图标 → 右上角 ⚙ → 填入 DeepSeek API Key → **测试连接** → **保存**

> ⚠️ **每次重新加载扩展后，必须刷新已经打开的网页**（F5）。
> 内容脚本在扩展重载后会失效，此时插件会明确提示「插件刚刚更新过，请刷新本页」。
> 如果看到这个提示，就是该刷新了 —— 不是保存按钮坏了。

**怎么确认页面跑的是最新脚本**：每次构建都会写入一个构建指纹，
显示在 `edge://extensions` 的扩展副标题上（形如 `dev.mv16b3kt`）。
插件打开时会拿页面脚本的指纹与扩展的指纹比对，不一致就直接提示刷新，
不必去猜控制台里的报错。

> API Key 在 <https://platform.deepseek.com> 创建。建议只充小额，并在平台侧设置用量上限。

### 怎么用

划词后，**鼠标位置**会弹出一条药丸按钮，点一下就在它右侧展开对话浮层：

| 方式 | 操作 |
|---|---|
| 做题 | 选中网页文字 → 点「✦ 做题」→ 浮层里直接给出答案 |
| 问 AI | 选中文字 → 点「💬 问 AI」→ 内容作为**引用**，你决定怎么问 |
| 截图提问 | 浮层顶栏的 ⛶ 按钮，框选区域即可；也可用右键菜单「截取区域问 AI」 |
| 快捷键 | `Alt`+`Shift`+`S`（未选中文字则自动改用网页正文） |
| 右键菜单 | 选中文字后右键 → 「用 AI 解答选中内容」；或「截取区域问 AI」 |
| 侧边栏 | 点扩展图标，打开完整对话视图 |
| 追问 | 直接在浮层底部输入框继续问，不必重新划词 |
| 移动浮层 | 按住**顶栏空白处**拖动 |
| 关闭 | `Esc`，或点浮层右上角 ✕ |

**浮层的开关**（顶栏从左到右）：📌 固定在最上层 · ⛶ 截图提问 · ⟲ 清空对话 · ⚙ 设置 · ✕ 关闭。
控制条上还有两个复选框：**引用网页正文**、**标注答案选项**。

**📌 固定**：默认点页面别处会关闭浮层；点一下 📌 就固定住，页面随便点都不消失。
这个选择会记进设置，下次打开还是固定状态。

**标注答案选项**：回答完成后，把「答案：B」对应的选项在网页上圈出来（绿色圈 + 徽标）。
**只做标注，不会替你勾选任何选项** —— 勾不勾由你决定。页面上有多道题时，
只标你正在做的那一组（靠选中文字定位）。

### 标注不生效？点 ⓘ 复制诊断信息

不同题库的选项写法差别极大（原生 radio、`<label>` 包裹、`div` 模拟、
字母画在别处……），所以浮层顶栏放了一个 **ⓘ 按钮**：
点它会收集"选项识别的真实情况"，并**自动复制到剪贴板**（按钮变成 ✓）。

内容包含：识别到几个原生 input、几个 role/div 候选、每个选项的字母及其来源、
容器描述、以及自动体检出的可疑点。把这段 JSON 发我即可定位问题。

里面还有一个 **`trace` 字段**（事件时间线），用于排查那些"点了没反应"的问题。
它把关键步骤都记下来，例如截图流程会依次出现：

```
script:loaded → panel:open → snapshot:click → capture:start
→ capture:overlay-ready → capture:confirmed → capture:bg-ok
→ snapshot:received → snapshot:panel-updated
```

看到**哪一步断了**就能直接定位，不用猜。几个典型读法：

| trace 内容 | 含义 |
|---|---|
| 空数组 | 脚本没加载（扩展没启用 / 页面是受限页） |
| 只有 `script:loaded` | 没打开过浮层，或浮层没渲染出来 |
| 有 `panel:open` 无 `snapshot:click` | 截图按钮没点到（或被 `disabled` 挡住） |
| 有 `snapshot:click` 无 `capture:start` | 被守卫挡住：模型正在流式回答时不允许截图 |
| 有 `capture:confirmed` 无 `capture:bg-ok` | **background 截图/裁剪失败**，`detail` 里有原因 |
| 有 `snapshot:received` 无 `snapshot:panel-updated` | 拿不到选区信息（`snapshot:no-payload`） |

常用的选项写法都已覆盖（见下方"设计决定 10"）；如果诊断显示
「没有找到任何 radio/checkbox」，说明那个站点用的是纯 `div` + 点击事件，
把选项那段 HTML 发我就能支持。

**引用不会占对话空间**：勾选「引用网页正文」后，正文只在发送请求时拼进 prompt，
对话气泡里只留一个来源小标签。这既省 token 也不刷屏。

## 二、当前已实现 / 未实现

**已实现**

- 划词药丸按钮贴在鼠标落点（不是选区末尾），跟随指针、贴边自动翻转
- 页面内浮层：Shadow DOM 隔离，支持「做题 / 问 AI」两种入口，可追问、可停止、可重试
- **浮层可拖动**（按住顶栏），**可固定在最上层**（📌，点页面别处也不消失）
- **截图提问**：框选页面区域 → 后台裁剪 → 通过 `deepseek-flash` 的图片输入直接作答。
  这是解决"跨域 iframe / canvas / PDF 里读不到文字"的正解
- **在网页上标注答案选项**：回答完成后把「答案：B」对应的选项圈出来。
  **只标注，不替你勾选**
- **对话在会话内保留，且按题目分行**：关掉浮层再打开，之前的问答还在（同标签页）。
不同题目的对话彼此独立 —— 换一道题会自动开一段新对话，不会把上一题的内容读回来。
「清空对话」会连存储一起清掉，模型下一轮也就没有历史了。

> 分行是按**题目文字**算出的短键（`conversationKey`）。最多保留 6 组对话，
> 超出会自动清理，避免 sessionStorage 无限增长。
- 侧边栏保留完整对话（两处共用同一套对话状态机）
- 页面正文提取：自动定位题干容器，把选项整理成 `A. / B. / C.` 结构
- **文本清洗**：题库常把字母、句点、选项文字拆在三个元素里，
  选中会得到 `A\n.\n100`。提取与展示前统一清洗成 `A. 100`
- 判断题 / 单选题的 `value="T"/"F"`、`<label><input>` 等常见版式
- 多题页面自动分题（`【第 N 题】`）
- 长消息自动折叠（可展开），不让一段题干占满整个浮层
- 思考模式开关（含推理强度），默认关闭以换取最快首字响应
- 答案行加大加粗高亮，一眼可见
- 引用以可编辑的小 chip 呈现，正文不进对话
- 自定义系统提示词、连接自检、清晰的中文错误提示（401/402/429 等）

**尚未实现**

- 会话历史跨页面/跨会话保留（目前只在同一标签页的会话内保留；刷新页面即清空）
- 导出对话

## 三、几个关键设计决定（都是实测得出的，不是拍脑袋）

### 1. 流式请求放在页面/侧边栏，不放 service worker

MV3 的 service worker **空闲约 30 秒就会被终止**，长连接的 SSE 放进去必然被腰斩。
侧边栏是持久扩展页面，适合干这件事。

前提是浏览器能直连 API。实测 `https://api.deepseek.com` 的 CORS 预检会
**精确回显 `chrome-extension://` 来源**并允许 `authorization` 头，所以可以直连，
不需要自建代理。这个结论值得记住——它省掉了整个后端。

### 2. 答题默认关闭思考模式

思考模式（`thinking`）**默认开启且 effort=high**，首字延迟很长。
对"快速答题"，速度就是全部价值，所以默认：

```jsonc
{ "thinking": { "type": "disabled" } }
```

遇到需要推理的难题，在设置里打开即可（可选 low / high / max）。

注意：思考模式下 `temperature`、`presence_penalty`、`frequency_penalty` **全部失效**，
`top_p` 只在 0.95–1.0 之间有效。所以客户端在思考模式下干脆不传这些参数。

### 3. 内容脚本必须完全自包含

Chrome 不支持把 ESM 当内容脚本加载。一旦 `content.js` 里出现顶层 `import`，
**内容脚本会静默失效**——不报错，只是划词没反应，极难排查。

因此：

- `src/content/` 下只允许 `import type`（编译期擦除）
- 消息常量在 `src/content/index.ts` 里有**一份就地副本**，与 `src/shared/constants.ts` 保持一致
- `vite.config.ts` 里的 `guardContentScript` 插件会在构建期检查 `dist/content.js`，
  一旦发现 ESM 语法就直接让构建失败

### 4. 选项字母只按顺序编号，不采信 `value`

判断题常写成 `value="T"` / `value="F"`（真值），不是选项字母。
早期版本"优先沿用站点 value"的实现会把「错误」标成 **F** 而不是 **B**，
模型据此就会答错。现在一律按组内 DOM 顺序编 A/B/C…，只要字母与文字一一对应，
模型就能正确作答。

同时避开了正则字符范围：`looksLikeOption` 用码点判断而不是 `[A-H]` 这类范围写法。

### 5. 不用 CRXJS

[CRXJS 对 `side_panel` 的 HMR 有问题](https://github.com/crxjs/chrome-extension-tools/discussions/765)，
而这个项目只有一个 HTML 入口，用一个薄 Vite 配置（多入口 + 两个小插件）更可控。

### 6. flex 纵向布局必须有一整条"确定的高度链"

这条踩过坑，改 CSS 前请先看 `styles.css` 里那段注释。

设置面板的保存按钮曾经**完全点不到** —— 因为 `.qa-settings` 用了 `height: 100%`，
而它的父级是**内容撑高**的，百分比高度在这种父级上会退化成 `auto`：
内容把页脚顶到容器外，再被 `overflow: hidden` 裁掉。

规则：从根到滚动容器，每一层要么有确定的 `height`，要么是受约束的 flex，
并且**都要带 `min-height: 0`**（flex 项默认 `min-height: auto`，会拒绝收缩，
滚动条就不会出现）。浮层本身用"受约束的 flex 列"（`min-height` + `max-height`
+ 内容自适应），所以它既不塌成一条，也不会超出视口。

### 7. Shadow DOM 里的 CSS 变量必须挂在能匹配到元素的选择器上

这条是"浮层还是透明"的真正原因，也是最容易反复踩的一个。

`:root` **在 shadow tree 里匹配不到任何元素** —— shadow root 不是元素，宿主是个
`<div>`。所以写在 `:root` 里的自定义属性根本不会进入 Shadow DOM，
浮层里所有 `var(--qa-*)` 全部失效：`background: var(--qa-bg)` 直接退化成透明，
边框、文字色也一起丢。

现在的做法（`injectStyles.ts` 的 `buildShadowCss()`）：把 `:root` 里的变量提取出来，
**直接声明在 `.qa-panel-root` 上**。它是所有面板样式的共同祖先，
变量能继承到全部后代，而且不依赖 `:host` 这类特殊选择器的支持
（顺带也让 jsdom 能跑回归测试 —— jsdom 不支持 `:host`）。

顺带在注入时补了 `box-sizing: border-box`：shadow tree 没有全局 reset。

> 教训：**jsdom 不做 `var()` 替换**（`background: var(--c)` 会原样返回字符串），
> 所以别指望断言"计算后的背景色"来发现问题。判断变量是否可用，
> 要做的是"用到的变量是否都有定义"这类字符串级断言 —— 见 `test-shadow-css.mjs`。

### 8. 扩展重载后的"上下文失效"必须明确告知用户

重新加载扩展后，**已经打开的页面**里的内容脚本还活着，但它持有的扩展上下文
已经作废：此时 `chrome.storage` 会抛 `Extension context invalidated`。

旧实现把这类错误当成"读取失败"静默降级为默认值，于是表现成
**"Key 保存不上、一直提示未配置、按钮点不动"**，让人以为是功能坏了 ——
实际上是页面该刷新了。这个坑用户连续踩了两次，所以现在有两道防线：

1. `storage.ts` 把这类异常区分为 `ExtensionGoneError`，浮层直接显示
   「插件刚刚更新过，按 F5 刷新本页」，而不是把用户带去一个存不进去的设置面板。
2. **构建指纹**（`buildInfo.ts`）：每次构建把 id 写进 manifest 的 `dshBuildId`，
   内容脚本读回来与自己的编译期常量比对。不一致 → 页面里跑的是旧脚本，
   一打开浮层就提示刷新。

指纹方案的好处是不依赖任何被作废的 API（`getManifest()` 本身失效就是证据之一），
而且能覆盖"扩展重载了但页面没刷新"这个**唯一**需要用户动手的场景。

判定刻意保守：受限页面（应用商店、PDF 阅读器）里 chrome API 本就不可用，
manifest 没有 build id 时也不做判断 —— 这两处都**不能**误报成"需要刷新"，
否则就从"静默降级"变成"误报要求刷新"，同样难用。

### 10. 选项识别要同时覆盖原生 input 与 div 模拟

只认 `input[type=radio]` 是不够的：不少在线判题系统用
`<div role="radio" class="option-item">A. xxx</div>` 这种写法，
按原方案会"一个选项都找不到"，表现为勾了「标注答案选项」却毫无反应。

`highlight.ts` 因此有两套收集逻辑，外加三条必要的判定规则：

**① 字母从哪来（优先级）**：文本里画出来的字母 → 整组可信的 `value` → 组内顺序。

**② 什么时候才信 `value`（踩过两次坑）**：单个 value 是 A–H 字母**不足以**
说明它是选项字母 —— 判断题常写 `value="T"/"F"`，其中 `F` 恰好落在 A–H 里，
但它是"错误"的**真值**，采信它就会把「错误」标成 F 而不是 B。

所以判据看**整组**：组内每个 value 都是单个 A–H 字母、且按 DOM 顺序恰好是
A、B、C… 时才算"站点在标注字母"（此时采信比按顺序猜更可靠）；
`T/F`、`1/2/3` 这类不构成序列，一律改用组内顺序编号。

> 顺带：这类判断一律用**码点比较**而不是 `/^[A-H]$/` 之类的字符范围正则 ——
> 范围正则在个别运行时上出现过意料之外的行为，而这里错了就是整题错。

**③ 圈多大**：可标注容器要取"最小"的。多个选项共用一个 `<label>` 时，
圈整块没有意义（会把整道题圈起来），所以退回 input；
但只圈 input 又太小（只有一个小圆点），于是向上找最近的、
**只包住这一个 input 且有自己文字**的祖先，让标注落在选项那一行上。

**④ 同一个字母上出现多个候选时怎么办**（真实页面踩到）：某在线考试系统里除了
4 个选项，还有一个 `name="confirm" value="on"` 的确认复选框。它拿不到字母，
会被"按组内顺序"编成 **A**，与真正的选项 A 撞车 —— 结果标注可能画在确认框上，
看起来像"没生效"。

所以候选按来源分级（`drawn` 文本里的字母 > `value` 整组可信 > `positional` 组内顺序），
同一字母只保留最可信的一档。诊断信息里的 `filteredOut` 就是被挤掉的杂项数量。

**⑤ 标注不能被页面裁掉**：标注层是 `fixed` 定位，而宿主页面若在祖先上设了
`overflow: hidden`，个别布局下会把它一起裁掉。所以定位坐标一律夹到视口内，
元素滚出视口时则隐藏（而不是飘在错误位置）。

### 9. 截图的完整链路

```
浮层 ⛶ 按钮
  → 先卸掉浮层与药丸条（否则它们会被截进图里）
  → 在 Shadow DOM 里画框选遮罩（选中区域挖空）
  → 用户确认后取走遮罩
  → content script 发 CAPTURE_REGION 给 background
  → background: chrome.tabs.captureVisibleTab → createImageBitmap 裁剪
    → OffscreenCanvas 转 JPEG(0.88) → base64 data URL
  → 作为 image_url 交给 deepseek-flash（单图最多计 1024 tokens）
```

**权限说明（为什么需要"读取所有网站"）**

安装时你会看到一次提示：*读取和更改你在所访问网站上的数据*。这是一次性确认，
之后不再询问。它来自 manifest 里的 `<all_urls>`，原因是：

- **划词浮标、读取题干、框选截图**都必须在你正在看的那个页面上运行，
  而扩展无法预知你会打开哪个题库；
- `chrome.tabs.captureVisibleTab` 需要 `activeTab` 或 `<all_urls>`，
  而 `activeTab` 只在"用户调用扩展"时临时授予（点扩展图标、扩展快捷键、右键菜单）
  —— **在网页里点浮层的按钮不算**。不加 `<all_urls>` 的话，⛶ 按钮会被浏览器拒绝：

  ```
  Either the '<all_urls>' or 'activeTab' permission is required.
  ```

- 划词脚本**本来就在所有网页上运行**（内容脚本的固有机制），
  `<all_urls>` 主要是把这项能力显式化，并让后台能调用截图接口。

首次安装会自动打开一个**权限说明页**，把"会做什么 / 不会做什么"讲清楚。

> ⚠️ **以后如果 manifest 的权限有变动，浏览器会自动停用扩展**，直到你重新确认。
> 去 `edge://extensions` 把开关打开即可 —— 这是浏览器的安全设计，不是出错。

**⚠️ 图片必须回到外层处理（踩过的坑）**

框选前会卸载浮层（否则浮层会被截进图里），**发起截图的 React 组件实例随之消失**。
所以图片回来后绝不能在组件内部调 `chat.ask()` —— 那是在更新一个已卸载组件的状态，
界面上毫无反应（表现成"截图成功但什么都没发生"）。

现在的流程是：组件把图片通过 `onSnapshot` 交回 `content/impl.ts`，
由外层带着图片**重新挂载浮层**（`PanelRequest.initialImage`），
`ChatPanel` 的"打开时执行一次"逻辑看到 `initialImage` 就直接发问。

同理，截图路径**不应预填草稿**：有图就直接问，不要再把之前选中的文字塞进输入框。

几个刻意的选择：

- **裁剪放在 background 用 OffscreenCanvas**，不在内容脚本里建 canvas 元素 ——
  内容脚本的 DOM 改动页面是能检测到的，能不做就不做。
- **先摘掉自己的 UI 再截图**，否则浮层会挡在题目上。取消截图时浮层会自动放回来，
  用户不必重新划词。
- **用 JPEG 而不是 PNG**：截图是给模型看的，JPEG 体积小得多，视觉理解对这点压缩不敏感。
- **按 devicePixelRatio 换算坐标**：选区是 CSS 像素、截图是物理像素，不换算就会裁偏。

### 12. 定位闪烁：为什么要"先隐形、定位、再显示"

用户看到过一次"点确定后屏幕左上角闪了一下"。原因是宿主元素的结构：

```
宿主: position: fixed; top: 0; left: 0; width: 0; height: 0   ← 零尺寸锚点
  └─ ShadowRoot
       └─ .qa-panel-root: position: absolute; left: 0; top: 0  ← CSS 默认在左上角
```

React 挂载后面板会先按 CSS 默认的 `left/top: 0` 渲染**一帧**，
JS 才量得到尺寸去摆位置 —— 那一帧就落在屏幕左上角。

修法是让"量尺寸 → 定位"在同一帧内完成，并且定位前不可见：

- `.qa-panel-root` 默认 `visibility: hidden`
- `positionPanel()` 设完 `left/top` 后加 `.qa-panel-positioned` 放行显示
- 入场动画的关键帧里也保持 hidden，到 70% 才强行显示 ——
  **兜住"定位一直失败"的情况**，否则面板会永久隐形（比闪一下更糟）
- 药丸条同理：量尺寸时用 `.qa-measuring`（参与布局但不画出来），
  定位完成后再加 `.qa-visible`

配套：`MountedPanel.size()` 在矩形全为 0 时回退到 CSS 声明的宽度 ——
否则布局尚未算出的那一瞬间会"永远定不了位"。

### 13. 截图权限：为什么最终选择了 `<all_urls>`

`chrome.tabs.captureVisibleTab` 需要 `activeTab` 或 `<all_urls>`，而 **`activeTab`
只在用户"调用扩展"时临时授予**（点扩展图标、扩展快捷键、扩展的右键菜单）。
在网页里点浮层的 ⛶ 按钮**不算**调用扩展，所以后台会拿到：

```
Either the '<all_urls>' or 'activeTab' permission is required.
```

一开始为了权限最小化刻意不加 `<all_urls>`，改成"引导用户走右键菜单"。
但这让最顺手的入口（⛶）不可用，得不偿失，最终决定申请。

**这个取舍值得记下来**：它对用户的心理成本主要来自安装提示
（"读取和更改你在所访问网站上的数据"）。而这个扩展的内容脚本本来就在所有网页上运行，
权限并没有实质变宽 —— 与其让用户对着权限列表猜，不如用一次说明页把
"为什么需要、会做什么、不会做什么"讲清楚。

配套做了三件事：

1. 首次安装自动打开权限说明页（`src/welcome/`），更新时不打扰
2. 截图失败时给出**可操作**的提示，而不是静默恢复浮层
   （静默失败曾让排查绕了好几圈 —— 见"设计决定 8"的同类教训）
3. `verify-dist.mjs` 断言 `<all_urls>` 与 API 域名都在，避免以后调权限时漏掉另一个

> 另外：**权限有变动时浏览器会自动停用扩展**，直到用户重新确认。
> 这是浏览器行为，说明页里也写了，免得用户以为装坏了。

### 目录结构

```
src/
  shared/
    constants.ts   设置类型、默认系统提示词、消息协议
    client.ts      DeepSeek SSE 流式客户端
    storage.ts     chrome.storage 设置读写
    useChat.ts     对话状态机（侧边栏与页面浮层共用）
    injectStyles.ts 共享样式字符串出口（?inline）
  entries/
    content.ts     内容脚本入口（交给 esbuild 打包）
  content/
    impl.ts        划词药丸条、采选区、定位浮层
    extract.ts     页面正文/题目提取（纯函数，可离线测试）
    ChatPanel.tsx  浮层里的对话界面
    mountPanel.tsx 把 React 挂进 Shadow DOM
  background/
    index.ts       service worker：开侧边栏、转发选区、右键菜单
  sidepanel/
    index.html     侧边栏入口
    App.tsx        侧边栏编排
    MessageList.tsx 消息渲染、思维链折叠、引用 chip
    Composer.tsx   输入框（full / compact 两种变体）
    SettingsPanel.tsx 设置
    Markdown.tsx   极简 Markdown 渲染（不碰 dangerouslySetInnerHTML）
    styles.css     共享样式（侧边栏 + 浮层都用这一份）
scripts/
  build.mjs        构建编排：Vite + esbuild 两步
  build-content.mjs 内容脚本自包含打包（含 ESM 语法护栏）
  verify-dist.mjs  产物校验（manifest 完整性、自包含性）
  test-extract.ts  提取器离线测试
```

### 构建为什么是两步

- **Vite** 负责侧边栏与 service worker —— 它们可以是 ESM，也能享受代码分割
- **esbuild** 负责内容脚本 —— 必须是**单文件、自包含的普通脚本**

内容脚本不能用 Vite：Vite 是多入口 + 代码分割，产物里必然留下
`import "./chunks/xxx.js"`，而 Chrome 不能把 ESM 当内容脚本加载。
**这个失败是静默的**（不报错，只是划词毫无反应），所以
`build-content.mjs` 与 `verify-dist.mjs` 都会在构建期直接判死。

### 一处安全设计

`Markdown.tsx` 全程构造 React 元素，**不使用 `dangerouslySetInnerHTML`**。
网页内容会进入模型上下文，模型输出可能被诱导包含 HTML/脚本，
只当纯文本渲染是必要防线，不是过度设计。

## 六、已知问题

- **跨域 iframe / canvas / PDF 里的题目读不到文字** → 用浮层顶栏的 ⛶ 截图提问，
  这是这类场景的正解。
- 浮层是 `fixed` 定位：滚动页面时它不会跟着选区走（已刻意不在滚动时关闭，
  避免你正在读答案时被打断）。
- 输入框内的选区会被忽略（避免打扰正常编辑）。
- 提取器是启发式的，特殊版式可能提取不全；此时可以只依赖划词或截图，
  或把设置里的「引用网页正文」关掉手动贴题。
- 截图走的是**可见区域**（`captureVisibleTab`），超出一屏的内容需要滚动后再截。
- 对话内容不跨页面保留：关掉浮层或刷新页面后重新开始。
